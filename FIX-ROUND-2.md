## B. Visual target (keep consistent with the earlier mock)
Navy header; white cards on `#EEF1F5`; one Primary per region; weights per addendum §D; spacing only 4/8/12/16/24; every text fully visible; every interactive element has a visible border/fill or an icon+label; nothing left as bare text.

## C. Process changes (mandatory)
1. **LayoutAudit must fail on trimmed text.** For every `TextBlock`, measure the untrimmed width with `FormattedText`; if it exceeds `ActualWidth` the audit fails. Whitelist: only the court/circuit grid cell and the «الاسم والقضية» second line **when marked ellipsis-allowed in code**. Names (sidebar, grid, wizard, card) and case numbers are never whitelisted.
2. **No-clip dialogs:** for every dialog at 1024×768 and 1366×768, assert content bounds ⊆ dialog bounds and the footer buttons are visible (hit-test their centers).
3. **Padding/Margin lint:** every custom `ControlTemplate` must bind `Padding` (`TemplateBinding`) if its style sets it.
4. **Real-use pass:** run the **published `dist\CourtDesk.exe`** (not the test host), render the main window, the wizard (steps 1–3 + success), the edit dialog, the backup screen and the roster preview at 1366×768 and 1024×768; save to `artifacts/round2/`.
5. **Defect-by-defect table in `PROGRESS.md`:** D1…D13 → «before image», «after image», «verified by test name». Open every PNG. A defect is closed only if the after-image visibly shows the fix.
6. Do not write "done" until the table is complete; then rebuild with `build.cmd`, update `dist\`, and report the new sha256.
